# FP8 KV Cache Knobs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add opt-in `CHAT_KV_CACHE_DTYPE` and `CHAT_CALCULATE_KV_SCALES` env knobs to the full stack's chat backend so a host can enable vLLM's FP8 quantized KV cache.

**Architecture:** Two conditional blocks in the chat service's existing shell-builder `command:` in `docker/compose.yaml` (the `set -- "$@" --flag` pattern every other optional chat flag uses), plus documentation in `.env.example` and CLAUDE.md. Unset knobs must leave the launched `vllm serve` argv byte-identical to today.

**Tech Stack:** Docker Compose, POSIX sh shell builder, vLLM CLI flags (`--kv-cache-dtype`, `--calculate-kv-scales`).

**Spec:** `docs/superpowers/specs/2026-08-03-fp8-kv-cache-design.md`

## Global Constraints

- Chat backend only; no other compose file or service changes.
- `CHAT_KV_CACHE_DTYPE` is passed verbatim — no value validation in shell (vLLM validates).
- `CHAT_CALCULATE_KV_SCALES` follows the boolean pattern: appended only when the value is exactly `true` (matching `CHAT_ENABLE_AUTO_TOOL_CHOICE`).
- No new defaults: both knobs unset → no new flags → current behavior.
- Repo hard rule: no production data and no absolute local paths in anything committed (scratch test scripts live in the session scratchpad, not the repo).
- There is no test suite for compose wiring; verification is a compose config render plus a stubbed-`vllm` argv simulation, both run from the repo root.

### Task 1: Wire the two knobs into the chat shell builder

**Files:**

**Interfaces:**
- Consumes: nothing from other tasks.
- Produces: env vars `CHAT_KV_CACHE_DTYPE` (string, verbatim) and `CHAT_CALCULATE_KV_SCALES` (`true` to enable) honored by the `chat` container. Task 2 documents exactly these two names.

- [ ] **Step 1: Write the failing argv-simulation test (scratchpad, not committed)**

Write this to `<scratchpad>/test_kv_flags.sh` (any session temp dir works; do not put it in the repo):

```bash
#!/bin/sh
# Extracts the chat command from compose config and runs it with a stubbed
# vllm, asserting the KV-cache flags appear only when the knobs are set.
set -eu
cd "$(git rev-parse --show-toplevel)"
STUB_DIR=$(mktemp -d)
trap 'rm -rf "$STUB_DIR"' EXIT
cat > "$STUB_DIR/vllm" <<'EOF'
#!/bin/sh
echo "$@"
EOF
chmod +x "$STUB_DIR/vllm"

CMD=$(docker compose --env-file .env.example -f docker/compose.yaml config --format json \
  | python3 -c 'import json,sys; print(json.load(sys.stdin)["services"]["chat"]["command"][0])')

run_chat() {
  env -i PATH="$STUB_DIR:/usr/bin:/bin" HOME="$HOME" "$@" sh -c "$CMD"
}

# Unset -> no KV flags
OUT=$(run_chat)
case "$OUT" in *kv-cache*|*calculate-kv-scales*) echo "FAIL: flags leak when unset"; exit 1;; esac

# Dtype set -> flag present with value
OUT=$(run_chat CHAT_KV_CACHE_DTYPE=fp8)
case "$OUT" in *"--kv-cache-dtype fp8"*) ;; *) echo "FAIL: dtype missing"; exit 1;; esac

# Scales true -> flag present; scales unset/false -> absent
OUT=$(run_chat CHAT_KV_CACHE_DTYPE=fp8 CHAT_CALCULATE_KV_SCALES=true)
case "$OUT" in *"--calculate-kv-scales"*) ;; *) echo "FAIL: scales missing"; exit 1;; esac
OUT=$(run_chat CHAT_KV_CACHE_DTYPE=fp8 CHAT_CALCULATE_KV_SCALES=false)
case "$OUT" in *"--calculate-kv-scales"*) echo "FAIL: scales leak when false"; exit 1;; esac

echo PASS
```

Note: the compose command string uses `export CUDA_VISIBLE_DEVICES=...` and only stubbed `vllm` is exec'd, so this runs safely on any machine, GPU or not.

- [ ] **Step 1: Add the .env.example lines**

Append to the Chat block in `.env.example`, directly after `# CHAT_CPU_OFFLOAD_GB=4`:

```bash
# CHAT_KV_CACHE_DTYPE=fp8              # quantized KV cache: ~halves KV memory (≈2x context/concurrency
#                                      # headroom at the same gpu-memory-utilization). fp8 resolves to
#                                      # e4m3 on CUDA; fp8_e5m2 trades precision for range and ignores
#                                      # scales. Composes fine with prefix caching. Unset = full precision.
# CHAT_CALCULATE_KV_SCALES=true        # calibrate K/V scales at startup (recommended with fp8/e4m3 —
#                                      # the default scale of 1.0 costs accuracy). For maximum accuracy
#                                      # use an llm-compressor-calibrated checkpoint via TEXT_MODEL.
```

`CHAT_KV_CACHE_DTYPE` / `CHAT_CALCULATE_KV_SCALES` follow this pattern:

chat is the only backend where this matters — embed/rerank are pooling
runners and Whisper's decode is tiny). Unset means full-precision KV
